# 2026.330.2042 — feat(pod): the KDE-over-VNC desktop with the org's full CDP surface

## Summary

A new pod: **`kde-vnc-cdp`** — pod-kde-vnc's fullscreen, GPU-accelerated KDE Plasma over VNC, with the
org's complete Chrome DevTools Protocol surface added, because that desktop could not be driven.

**The stack, in ONE container on the CDI GPU pod base (`podcdi.pod-cdi`):**

```
sway (headless, pod-sway)  ── wayland-0 ──►  wayvnc (pod-wayvnc)  ── :5900
    └─ KWin (nested, --socket wayland-kde) as sway's ONE fullscreen window
          └─ plasmashell + KDE apps
          └─ Chrome (supervised, maximized)  ── cdp-proxy :9222 ──►  cdp: verbs, $BROWSER
                                            └─ chrome-devtools-mcp :9224 ──►  MCP clients
```

- `kde-vnc-cdp-session` composes `pod-kde-vnc`'s `kde-vnc-session` (sway + wayvnc + the shared nested
  Plasma session + the image's session env) and `pod-chrome-cdp`'s `chrome-cdp` (chrome-wrapper,
  cdp-proxy on 9222, browser-open, chrome-restart, the chrome-windows extension, BROWSER /
  BROWSER_CDP_URL, and the composed `chrome-devtools-mcp` on 9224). Its own contribution is the
  SUPERVISED `chrome` service on `/tmp/wayland-kde`, and one pinned `plugin-cdp` release (the one
  that fixes `close`'s tab resolution and bounds the screenshot, opencharly/plugin-cdp#15).
- Ports are inherited: **5900** VNC, **9222** CDP, **9224** MCP. The image declares none.
- Chrome runs as a PLASMA window on `wayland-kde` — `wayland-0` is the compositor BEHIND the
  fullscreen KWin window, where a browser renders itself invisible — supervised, so the init system
  waits for the socket and restarts it on exit, and maximized (asserted from BOTH sides, see below).

**Two beds, both `disposable: true`:**

- `check-kde-vnc-cdp-pod` — the pod: services, KWin fullscreen + hardware GL, Chrome a maximized KWin
  client, every `cdp:` method, the MCP bridge, `$BROWSER` and `chrome-restart`, and VNC watch + drive.
- `check-cross-kde-cdp-pod` — **the pod-to-pod cross-deployment CDP mechanism's only witness**
  (opencharly/distro-fedora#140): the KDE pod's Chrome renders a SEPARATE CachyOS fixture pod
  (`kde-web-subject`) over the shared `charly` net via `${HOST:check-cross-kde-cdp-pod}:8080`, and
  the VNC frame shows that cross-pod page. Its Fedora predecessor (`check-cross-pod-cdp`, driving the
  retired `chrome-headless`) was deleted with opencharly/distro-fedora#138, leaving the mechanism
  unproven — this is its successor, on CachyOS+KDE.
